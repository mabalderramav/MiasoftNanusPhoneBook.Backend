# MN-17 — Share `ToErrorResult` in `ProblemDetailsHelper` and add `.ProducesProblem` OpenAPI metadata

## Goal

This plan covers the two "Optional follow-up" items from MN-10.

1. **Remove the duplicated `ToErrorResult`.** `UserEndpoints` and `AgendaEndpoints` each have a private
   `ToErrorResult(Result)` with the same rule: return 404 if the error is one of a given set, otherwise 400.
   Move that rule into `ProblemDetailsHelper` as `ToErrorResult(Result result, params Error[] notFoundErrors)`
   and delete both local copies.
2. **Document error responses in OpenAPI.** Handlers return `IResult`, so `AddOpenApi()` cannot infer the
   400/404 responses. The generated document only lists the 200 response. Add `.ProducesProblem(400)` and
   `.ProducesProblem(404)` to each endpoint so the spec says these responses use
   `application/problem+json` with a `ProblemDetails` schema.

- **Shared code:** `src/MiasoftNanus.PhoneBook.WebApi/Shared/ProblemDetailsHelper.cs`
- **OpenAPI setup:** `Program.cs` (`builder.Services.AddOpenApi()` / `app.MapOpenApi()`, package
  `Microsoft.AspNetCore.OpenApi` 10.0.9)
- **Example module:** `Locations/Endpoints/LocationEndpoints.cs`. Do it first and use it as the reference
  for the other modules.

## Part A — `ProblemDetailsHelper.ToErrorResult`

### A.1 Add the helper

Add this to `ProblemDetailsHelper` (`Error` and `Result` come from `Domain.Abstractions`, which is already
imported):

```csharp
/// <summary>
/// Maps a failed operation result to an HTTP error result: 404 Not Found when the result error is one of
/// <paramref name="notFoundErrors"/>, otherwise 400 Bad Request. Both use a <see cref="ProblemDetails"/> body.
/// </summary>
/// <param name="result">The failed operation result.</param>
/// <param name="notFoundErrors">The domain errors that mean "resource not found".</param>
/// <returns>A 404 or 400 <see cref="IResult"/> whose body is <see cref="ProblemDetails"/>.</returns>
public static IResult ToErrorResult(Result result, params Error[] notFoundErrors)
{
    return notFoundErrors.Contains(result.Error)
        ? TypedResults.NotFound(CreateNotFoundProblemDetails(result))
        : TypedResults.BadRequest(CreateBadRequestProblemDetails(result));
}
```

Notes:
- `Error` is a `record` (`Domain/Abstractions/Error.cs`), so `Contains` uses value equality. This is the
  same comparison as the current `==` checks.
- If `notFoundErrors` is empty, the method always returns 400. That is intended.
- `IResult`/`TypedResults` come from the Web SDK implicit usings, and `Contains` comes from `System.Linq`.
  No new `using` should be needed. Add `using Microsoft.AspNetCore.Http;` only if the build asks for it.

## Part B — `.ProducesProblem(400/404)` OpenAPI metadata

### Pattern (from LocationEndpoints)

```csharp
// before
locationGroup.MapGet("/{id:guid}", GetLocationById);

// after
locationGroup.MapGet("/{id:guid}", GetLocationById)
    .ProducesProblem(StatusCodes.Status404NotFound);
```

- Use `StatusCodes.Status400BadRequest` / `Status404NotFound` constants, not literal numbers.
- Only declare the codes a handler can actually return (see the tables). Do not put a blanket
  `.ProducesProblem(...)` on the `MapGroup`, because then `POST` would advertise a 404 it never returns.
- Chain after any existing calls (`.Accepts<...>`, `.DisableAntiforgery()`, ...).
- This does not change runtime behavior. It only adds endpoint metadata.

## Optional follow-up (out of scope)

- Add `.Produces(StatusCodes.Status401Unauthorized)` to `DeleteAgenda` / `DeletePhotoAgenda`, and maybe
  describe the `X-Api-Key` header as an OpenAPI security scheme.
- Add `.ProducesProblem(500)` on each group to document the `GlobalExceptionHandler` response.
- Add success metadata (`.Produces<TDto>(200/201)`, `.Produces(204)`), or switch handlers to
  `Results<Ok<T>, NotFound<ProblemDetails>, ...>` return types so the framework infers all of this. That
  change is larger and would make the manual `.ProducesProblem` calls unnecessary.
- `GET /` returning 404 when the collection is empty (all modules) is questionable REST. It should probably
  be `200 []`. That is a separate issue.
