# MN-10 — Return ProblemDetails from all endpoint error responses

## Goal

Endpoints currently return the raw domain `Error` (`{ code, message }`) as the body of 400/404 responses.
Replace it with an RFC 7807 `ProblemDetails` body built by the shared helper, so every error response
has the same shape as the ones produced by `GlobalExceptionHandler`.

- **Shared code:** `src/MiasoftNanus.PhoneBook.WebApi/Shared/ProblemDetailsHelper.cs`
  - `CreateNotFoundProblemDetails(Result result)` → `Status = 404`, `Title = Error.Code`, `Detail = Error.Message`
  - `CreateBadRequestProblemDetails(Result result)` → `Status = 400`, same mapping
- **Example:** `src/MiasoftNanus.PhoneBook.WebApi/Locations/Endpoints/LocationEndpoints.cs` (done)

## Pattern (from LocationEndpoints)

```csharp
using MiasoftNanus.PhoneBook.WebApi.Shared;

// before
return TypedResults.NotFound(result.Error);
return TypedResults.BadRequest(result.Error);

// after
return TypedResults.NotFound(ProblemDetailsHelper.CreateNotFoundProblemDetails(result));
return TypedResults.BadRequest(ProblemDetailsHelper.CreateBadRequestProblemDetails(result));
```

The helper takes the whole `Result` (not `result.Error`). `Result<T>` inherits from `Result`, so both
work as arguments.

## Scope

Not changed: success responses, `TypedResults.Unauthorized()` (X-Api-Key checks), `TypedResults.Stream`,
the HTTP status code chosen for each case, and the `IResult` return types.

parameter to `Result` and update its callers (`UpdateUser`, `PatchUser`, `ChangeUserPassword`):

```csharp
// A missing user is a 404; any other failure (validation, unknown profile, ...) is a 400.
private static IResult ToErrorResult(Result result)
{
    return result.Error == UserErrors.UserNotFound
        ? TypedResults.NotFound(ProblemDetailsHelper.CreateNotFoundProblemDetails(result))
        : TypedResults.BadRequest(ProblemDetailsHelper.CreateBadRequestProblemDetails(result));
}

// callers
if (result.IsFailure)
    return ToErrorResult(result);
```

Add the `Shared` using. Keep `Domain.Abstractions`; it is still needed for `Result`.

## Optional follow-up (out of scope)

- Both `ToErrorResult` methods follow the same "404 if one of these errors, else 400" pattern. They could
  move into `ProblemDetailsHelper` as `ToErrorResult(Result result, params Error[] notFoundErrors)`.
  This plan keeps them local to stay close to the Locations example.
- `ProfileEndpoints.CreateProfile`/`UpdateProfile` return `result.Value` (the entity) instead of
  `result.Value.ToDto()`. This is not part of this ticket, but it is worth a separate issue.
- Add `.ProducesProblem(400/404)` metadata for OpenAPI.
